# v0.4 冻结基线与回归矩阵

本文档冻结 v0.3 的高风险行为，并把每个 P0/P1 映射到 v0.4 的确定性测试或显式删除决定。测试数据全部为合成内容；不得把真实 prompt、路径内容、Queue 文本、凭据或已解密 Relay payload 复制到 fixture。

## 严重级别

- **P0**：安全边界突破、状态库损坏、重复外部副作用或无法恢复的秘密泄漏。
- **P1**：核心流程阻断、任务无法权威恢复、Queue 错投、审批错误归属或静默协议降级。
- P2/P3 不阻止 v0.4 架构替换，但必须进入后续 issue；不得借此降低 P0/P1。

## 探索性场景矩阵

每个 staging 候选版本必须覆盖下列笛卡尔维度；`R` 表示发布必跑，`S` 表示抽样但不得长期固定在同一组合。

| 维度         | 取值                                                     |        Direct |         Relay |
| ------------ | -------------------------------------------------------- | ------------: | ------------: |
| 视口         | 390×844 手机 / 桌面 Chrome                               |         R / R |         R / R |
| 设备         | 首次配对 / 已保存设备 / 新设备临时登录                   |     R / R / R |     R / R / R |
| Web 身份     | Passkey / CE 密码 / 恢复码                               |     R / R / R |     R / R / R |
| Codex 初始化 | 未安装 / 未登录 / ready                                  |     R / R / R |     S / R / R |
| task 状态    | idle / running / waiting-input / failed                  | R / R / R / S | R / R / R / S |
| 连接故障     | 浏览器断线 / Agent 重启 / app-server 重启                |     R / R / R |     R / R / R |
| Queue        | add / remove / steer / crash-indeterminate / acknowledge |             R |             R |
| 更新         | 无更新 / waiting SW / API 版本不匹配                     |             R |             R |

当前实机发布门槛只覆盖一个真实用户。管理端、多用户并发和跨用户隔离继续由自动化回归保护，真实环境验收移入后续里程碑，不作为当前单用户 production 的阻塞项。

## 核心行为清单

1. app-server 始终是 thread、turn、item、interaction 和运行状态的唯一事实源。
2. `thread/open` 返回快照、history cursor、状态、设置和当前 interaction；Web 不从事件缺口推断状态。
3. mutation 全部携带 UUID operation key；query 拒绝 operation key。
4. 未知 Codex notification 必须成为 `codex/generic`，不得崩溃或丢弃。
5. Direct 与 Relay 共享同一 v2 router/session；Relay 不拥有明文业务 dispatch。
6. 临时会话关闭后不留下 Host Profile、设备密钥或业务缓存。
7. 所有 SQLite 访问位于 repository；所有 client、timer 和 listener 随 Scope 关闭。
8. 正向和反向迁移在正式替换前验证计数、领域不变量、owner、权限、完整性和备份 SHA。
